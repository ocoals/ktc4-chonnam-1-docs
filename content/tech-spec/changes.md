## 2. 언제 무엇을 정했나

| 날짜 | 결정 | 근거 |
| --- | --- | --- |
| 2026-09-13 | CI는 의존성 관리 방식이 정해진 뒤 추가한다 | 커밋 기록 |
| 2026-09-18 | `ai/`를 로컬 패키지로 둔다. 격리 환경을 별도 서버로 둔다. 카카오 콜백에 의존한다. LLM 호출 예산은 호출 단계가 소유한다 | ADR 0001–0004 |
| 2026-09-26 | 동의는 문자를 외부로 보내기 직전 한 곳(W3)에서만 받는다. BE 동의 기록 전에는 W3를 배포하지 않는다. 결과 확인은 별도 블록에서 한다 | chatbot-flow 9절, PR #24 리뷰 |
| 2026-10-17 | urlscan을 없애고 모든 링크를 자체 격리 수집기로 모은다. 공개 수집 모드를 EC2에 적용했다 | ADR 0002 이후 변경, `docs/experiments/2026-10-17-*` |
| 2026-10-27 | 에이전트 루프를 접는다. LLM은 주장·요구를 인용과 함께 읽고 결론·질문·안내는 코드가 정한다. 결과 카드의 신고 버튼을 Q1으로 바꾼다 | D15·D16 |
| 2026-10-30 | 링크 추출을 요구 분석 LLM으로 옮긴다 | ADR 0007 |
| 2026-10-31 | 통화 녹음의 화자 분리를 없애고 문장 꼴로 받는 사람 쪽 말을 거른다 | ADR 0008 |
| 2026-11-03 | 상세 웹을 만들지 않는다(결과 웹 제안 기각) | ADR 0005 채택, ADR 0006 기각 |
| 2026-11-04 | 여러 링크를 모두 검사한다. R3·R7 카드를 지운다. 범위 밖 입력을 따로 가리지 않는다. 자주 사칭되는 공공기관은 주의까지만 쓴다 | D7·D3·D4 철회, ADR 0010 |
| 2026-11-06 | 브라우저 수집을 거쳐도 경로가 모두 공식이면 공식 판정을 유지한다. 격리 수집기를 다시 배포했다 | ADR 0009, `docs/isolation-collector-api.md` |

## 3. FE

## 8. 남은 일 (미구현과 열린 결정)

1. **외부 전송 동의.** 지금은 사람 게이트가 0곳이다. 밖으로 나가는 것은 문자 원문과 페이지 내용(LLM API), 녹음(STT API), 그리고 격리 서버의 링크 접속이다. 수신자별 토큰이 든 링크를 열면 공격자는 "이 번호가 살아 있다"를 알게 되고 1회용 링크는 소모된다(`docs/isolation-security.md` 5.8). 동의 카드 W3·W3v는 만들어 두었다.
2. **결과 보관·삭제 정책과 영속 저장소.** 메모리 저장이라 재시작이나 인스턴스가 여럿일 때 결과 확인·Q1 답·중복 방지가 깨진다.
3. 링크 결과(R1·R9) 아래 Q1(D16)과 A3 카드.
4. 다중 링크 요약 말풍선·캐러셀(`chatbot-copy.md` 3절 초안).
5. 공식 도메인 즉답(D2). 지금은 공식 주소도 R5와 콜백을 거친다.
6. 정적 검사(KISA 목록, Punycode) 연결, 도메인 등록일 조회.
7. `docs/security-checklist.md`의 미체크 5건: 프롬프트 인젝션 분리, 원본 HTML 전달, 원문 로깅 정책, LLM 출력 가드, `.env` CI 검사.
8. CI에서 테스트 실행.
9. 사용자 테스트(PRD 2-3의 10건은 모두 `[미실행]`)와 오탐·누락·보류율 측정.

## 9. 비교하다 발견한 것 (확인 필요)

1. `CLAUDE.md`와 `docs/PRD.md`는 "근거가 검증된 신호만 `ai/verdict.py`의 `decide()`가 판정에 쓴다"고 적는다. 운영 경로(`main.py`)는 `decide()`를 부르지 않는다. `decide()`는 `ai/tests/test_verdict.py`에서만 쓴다. 링크 결과를 실제로 가르는 곳은 `main.py` `build_ai_url_analysis()`(공식 대조·강등)와 `services/result_card_selector.py` `select_result_card()`(카드 선택)이고, 신호 근거 검증은 `ai/src/ai/pipeline/results.py`가 한다. v2 스펙은 실제 경로 기준으로 적었다.
2. `docs/PRD.md` 3-1·3-2에는 ④ 대조 LLM, ⑤ 보강 판단 루프, "모델 호출 3곳"이 미구현 표시 없이 남아 있다.
3. `ai/README.md`에는 `Observations`·`split_message` 시절 설명이 남아 있다. 지금 입력은 `IsolatedPage`이고 링크 추출은 `read_message`다.
4. 링크가 4개 이상이고 모두 읽혔으면(`unverified_links = False`) 응답 말풍선이 3개를 넘는다. `run_analysis()`는 못 읽은 링크가 있을 때만 3개로 자른다. 카카오 상한에 걸려 콜백이 거절될 수 있다. 테스트는 읽힌 링크 3개까지만 본다(`tests/test_read_message_flow.py`). 실기기에서는 확인하지 않았다.
5. 링크마다 수집(최대 17초)과 페이지 분석(5초)을 차례로 돈다. 최악에는 링크 2개만으로도 45초 상한에 걸리고, 이미 끝낸 링크의 결과까지 시간 초과 안내로 바뀐다. `docs/latency-budget.md`도 여러 URL이 같은 45초 예산을 나눠 쓴다고 적는다.

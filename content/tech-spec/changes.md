# 처음 설계에서 바뀐 것

0주차에 쓴 처음 기술 스펙과 2026-11-10의 실제 서비스를 비교했습니다. 이유는 ADR, 설계 문서의 결정 기록, 커밋 메시지, 코드 주석에서 찾았고, 이유가 남아 있지 않은 항목은 **기록 없음**으로 적었습니다.
바뀐 내용을 반영한 설계는 [테크스펙 본문](#overview)에 있습니다.

## 1. 한눈에 보기

| 항목 | 처음 설계 | 지금 | 왜 바뀌었나 |
| --- | --- | --- | --- |
| 범위 | 택배 사칭에서 피싱 7유형으로 넓히고, 유형별 규범을 RAG로 관리 | 세 시나리오: 링크가 있는 문자, 링크가 없는 사칭 문자(가족, 지인, 기관), 통화 녹음 | 링크만 보면 링크 없이 가족이나 기관을 사칭하는 문자를 다루지 못한다는 지적을 받아 시나리오로 넣었습니다. 통화 녹음도 같은 틀로 함께 다룹니다 |
| 판정 구조 | LLM 대조와 보강 판단 에이전트 루프 | LLM은 읽기와 근거 있는 신호 제안만 하고, 갈림길과 결론은 코드가 정합니다 | LLM과 코드의 역할을 분명히 나눠야 한다는 지적에 따라 2026-10-27 에이전트 루프를 접었습니다. 결론을 재현하고 설명할 수 있게 하려는 것입니다 |
| 관측 | urlscan 같은 외부 분석 API | 자체 격리 수집기(EC2) | urlscan은 약 30초가 걸리고 통제할 수 없었습니다(ADR 0003). 격리 경계를 프로세스가 아니라 서버로 둡니다(ADR 0002) |
| 화면 | 카카오 응답과 Next.js 웹 | 카카오 카드만. 웹은 없습니다 | 카드와 캐러셀로 근거를 보여 줄 수 있었고, 웹은 토큰, 조회 API, 배포 대상을 늘립니다(ADR 0005 채택, ADR 0006 기각) |
| 저장소 | PostgreSQL, 작업 큐, Vector DB | 프로세스 메모리. KB는 저장소 안 파일 | 프로토타입 검증 속도를 먼저 챙겼습니다. 영속 저장소는 추후 개선 사항입니다 |
| AI 배치 | 별도 AI 서비스를 JSON으로 호출 | `ai/` 패키지를 같은 프로세스에서 함수로 호출 | 5초 예산 안에서 네트워크 왕복과 콜드 스타트를 없앱니다(ADR 0001) |
| 링크 개수 | 1개만. 0개나 2개 이상이면 되묻기 | 여러 개면 모두 검사하고, 0개면 사칭 문자로 분석 | 첫 주소만 검사하면 나머지가 위험할 때 잘못된 안심을 줍니다. 링크 없는 문자에도 결론을 줍니다 |
| 링크 추출 | 정규식 | LLM이 뽑고 코드가 원문과 대조 | 정규식은 바꿔 적은 주소, 조사가 붙은 주소, `@` 위장 주소를 놓칩니다(ADR 0007) |
| 동의 | 조사 시작 버튼으로 동의 | 개인정보 처리 안내 카드로 알리고, 동의 카드는 준비해 둠 | 동의 기록을 저장할 곳이 생긴 뒤 동의 카드를 붙이기로 했습니다 |
| 결과 상태 | 신호 있음, 추가 조사, 범위 안 신호 없음, 보류의 4값 | 링크 문자는 결과 카드 4종, 링크 없는 문자와 통화는 결론 5값 | 판정 근거가 공식 도메인 대조와 검증된 신호로 바뀌었습니다 |
| 응답 시간 | 신호와 RAG 1초, 관측 포함 60초 | 첫 응답은 5초 안에 대기 글, 결과는 콜백, 전체 45초 | LLM이 링크를 뽑아야 링크가 있는지 압니다(ADR 0007). 콜백 주소의 유효 시간을 고려해 45초로 줄였습니다(ADR 0003) |
| RAG | pgvector, 해석이 규범 ID를 인용 | 파일 KB와 메모리 하이브리드 검색(TF-IDF와 임베딩). 사례는 참고용, 규범은 공식 확인 방법 안내에만 | 판정은 결정적 로직이 합니다. 검색된 규범이나 사례로 판정하지 않습니다 |
| 빠진 기능 | 조회 한도, 재조회, 진행 체크리스트, 관측 시각 표시, 삭제 요청 | 조회 한도는 필요 없어졌고, 나머지는 추후 개선 사항입니다 | 루프가 없어 한도가 필요 없습니다. 진행 체크리스트는 콜백 대기 응답에 카드를 넣을 수 없는 카카오 제약 때문에 뺐습니다 |

## 2. 언제 무엇을 정했나

| 날짜 | 결정 |
| --- | --- |
| 2026-09-18 | `ai/` 를 로컬 패키지로 둔다. 격리 환경을 별도 서버로 둔다. 카카오 콜백에 의존한다. LLM 호출 예산은 호출 단계가 정한다 (ADR 0001, 0002, 0003, 0004) |
| 2026-09-26 | 동의는 문자를 외부로 보내기 직전 한 곳에서만 받는다. 결과 확인은 별도 블록에서 한다 |
| 2026-10-17 | urlscan을 없애고 모든 링크를 자체 격리 수집기로 모은다 |
| 2026-10-27 | 에이전트 루프를 접는다. LLM은 주장과 요구를 인용과 함께 읽고, 결론, 질문, 안내는 코드가 정한다. 결과 카드의 신고 버튼을 질문 카드로 바꾼다 |
| 2026-10-30 | 링크 추출을 요구 분석 LLM으로 옮긴다 (ADR 0007) |
| 2026-10-31 | 통화 녹음의 화자 분리를 없애고 문장 꼴로 받는 사람 쪽 말을 거른다 (ADR 0008) |
| 2026-11-03 | 상세 웹을 만들지 않는다 (ADR 0005 채택, ADR 0006 기각) |
| 2026-11-04 | 여러 링크를 모두 검사한다. 겹치는 결과 카드를 정리한다. 범위 밖 입력을 따로 가리지 않는다. 자주 사칭되는 공공기관은 주의까지만 쓴다 (ADR 0010) |
| 2026-11-06 | 브라우저 수집을 거쳐도 경로가 모두 공식이면 공식 판정을 유지한다 (ADR 0009) |

## 3. FE

| 처음 설계 | 지금 | 왜 |
| --- | --- | --- |
| 템플릿 함수와 출력 가드, Next.js 웹 | 카드 JSON 41개를 BE 렌더러가 채웁니다. 웹은 없습니다 | 1절의 화면 항목과 같습니다 |
| 근거 카드 4칸(문자 주장, 관측, 해석, 미확인) | 결과 카드 본문과 `자세히 보기` 캐러셀로 나눕니다. 본문에는 `확인한 것`, `확인하지 못한 것` | 카카오 글자 수 제약(버튼 14자, 본문 230자) 때문입니다. 해석을 쓰는 LLM이 없어 해석 칸은 뺐습니다 |
| 진행 체크리스트 | 대기 글 한 장 | 콜백 대기 응답에는 카드와 버튼을 넣을 수 없습니다 |
| 5초 안에 못 끝낼 때만 "조사 중" 안내 | 모든 문자와 녹음이 대기 글을 거쳐 콜백으로 갑니다. 결과가 안 오면 「결과 확인」을 보냅니다 | 첫 응답 5초 안에는 링크가 있는지 모릅니다. 콜백이 실패했을 때 닿는 길은 사용자 입력뿐입니다 |
| 추출 결과를 보여 주고 조사 시작 확인 | 보내면 바로 분석합니다 | 추출이 첫 응답 뒤에 끝납니다 |
| 판단 보류(확인된 것, 부족한 것, 결론) | "판단하기 어려워요"(확인한 것, 확인하지 못한 것, 문자에 적힌 내용)와 분석 실패 카드로 나눕니다 | 정보 부족 카드와 판단 보류 카드가 겹쳐 하나로 합쳤습니다 |
| 범위 밖이면 판정 없이 범위 밖이라고 안내 | 모든 입력을 분석하고, 사칭이나 요구가 없으면 찾지 못했다고 답합니다 | 범위를 가리는 규칙을 따로 두지 않기로 했습니다 |
| 의심 URL을 누를 수 없게 표시 | 결과 카드에 의심 URL을 아예 싣지 않습니다 | 싣지 않으면 눌릴 일도 없습니다 |
| 근거마다 관측 시각과 출처 | 결과 확인 시각만 보여 줍니다 | 웹을 만들지 않아 원자료를 보여 줄 곳이 없습니다 |
| (없음) | 질문 카드 "이미 하신 게 있나요?", "원래 알던 번호로 통화해 보셨나요?" | 상황에 맞는 대응을 고르게 합니다. 신고 버튼과 질문이 같은 것을 물어 질문으로 합쳤습니다 |
| (없음) | 신고 상담 메뉴(KISA 118, 1394, 112) | 이미 링크를 누른 사람은 확인보다 상담이 먼저입니다 |
| (없음) | 녹음 입력, 녹음 결과 카드, 녹음 보내는 법 | 통화 시나리오를 더했습니다 |

| 내부 API 7개 | 개발, 테스트용 작업 조회 API 하나 | 웹이 없어 조회 API가 필요 없습니다 |
| 작업 상태 6개와 단계 기록 | `running` 에서 `completed`, `failed`, `timeout` 중 하나로 | 진행 체크리스트와 루프가 없습니다 |

| BE는 판단 로직을 갖지 않는다 | 공식 도메인 대조와 결과 카드 선택은 BE 코드입니다. LLM 프롬프트는 BE에 없습니다 | 화이트리스트 대조는 BE가 맡는다는 경계를 지켰습니다 |
| 공식 확인 경로 DB | 공식 도메인은 코드 상수(택배, 쇼핑 11개 업체), 공식 확인 방법은 AI KB, 신고 창구는 카드의 고정 버튼 | 확인된 도메인만 사람이 등재하고, 추측으로 채우지 않습니다 |
| 관측 내용을 따로 격리, 페이지 스크립트 미실행 | 의심 URL에는 격리 서버만 접속하고, 메인 서버는 정해진 필드만 받습니다. 격리 서버의 Chromium은 필요할 때 스크립트를 실행합니다 | 정적 HTML만으로는 스크립트로 이동하는 페이지를 볼 수 없습니다 |
| (없음) | 콜백 주소 허용 목록, 녹음 다운로드 허용 목록과 공인 IP 확인, 녹음 25 MB 상한 | 내부 주소로 결과를 보내거나 내려받게 만드는 요청을 막아야 한다는 지적을 반영했습니다 |
| (없음) | 통화 경로: 녹음 받기(15초), 형식 검사, 받아쓰기(30초), 통화 분석(남은 시간) | 통화 시나리오를 더했습니다 |

## 5. AI

| 처음 설계 | 지금 | 왜 |
| --- | --- | --- |
| 해석, 유형 분류, RAG 규범, 관측, 대조 LLM, 보강 루프, 조립의 순서 | 문자 읽기, 사례 검색과 신호 제안과 격리 수집을 함께, 공식 대조, 페이지 검사, 결과 조립, 카드 선택 | 1절의 판정 구조 항목과 같습니다 |
| 유형 7종 분류와 confidence | 업체, 주제, 요구 행동을 인용과 함께 뽑습니다. 링크 없는 문자와 통화는 신분과 요구 주장을 읽습니다. confidence는 없습니다 | LLM이 유형을 고르는 대신 근거가 있는 주장을 읽게 했습니다 |
| 해석이 RAG 규범을 인용 | 규범은 결과에 맞는 공식 확인 방법을 최대 3개 고르는 데만 씁니다 | 검색된 규범으로 판정 규칙을 만들지 않습니다 |
| 유사 사례는 보조 근거 | 사례(문자 502건, 통화 127건)를 TF-IDF와 임베딩으로 찾습니다. 판정에는 쓰지 않습니다 | 유사도는 악성 확률이 아닙니다 |
| 발신번호, 국제발신, 단축 URL, 도메인 등록일 같은 결정적 신호 | 공식 도메인 대조, 단축 URL 해석, 브라우저 경유지 보류, 페이지 요소 검사, 공식 대표번호 대조, 공공기관 주의 | 입력이 문자 원문과 녹음이라 발신번호는 보지 않습니다. 정적 검사 연결과 등록일 조회는 추후 개선 사항입니다 |
| 대조 LLM 1회 | 문자와 페이지를 따로 LLM이 위험 신호와 근거로 제안하고, 코드가 근거가 실제 입력에 있는지 확인합니다 | 1절의 판정 구조 항목과 같습니다 |
| 보강 판단 루프와 조회 한도 | 없습니다 | 루프를 접었습니다. 처음 설계에 적은 "적응형이 낫다는 근거가 없으면 고정 단계로" 규칙과 같은 형태입니다 |
| 판단 호출은 3곳 | 링크 문자 1건에 읽기 1번, 신호 제안 1번, 링크마다 페이지 검사 1번. 어느 호출도 판정하지 않습니다 | |
| 설명문은 LLM 출력 | 사용자에게 보이는 문장은 코드 템플릿이 만듭니다 | LLM이 실패해도 응답은 나가야 합니다 |
| 인젝션 테스트셋 | 프롬프트가 입력을 명령이 아닌 분석 대상으로 구획하고, 근거는 요소 ID와 원문만 받습니다 | 인젝션 문구를 넣은 평가셋은 추후 개선 사항입니다 |
| 임베딩 모델 미정 | text-embedding-3-large. LLM, STT도 OpenAI 호환 API로 부릅니다 | |
| (없음) | 통화 분석: whisper 받아쓰기, 주장 읽기, 문장 꼴로 받는 사람 쪽 말 거르기, 결론 관문, 질문 카드 | 화자 분리가 느렸고(평균 4.9초) 사례 데이터에 화자 표기가 없었습니다(ADR 0008) |
| (없음) | 자주 사칭되는 공공기관 8곳은 주의와 대표번호 안내까지만 씁니다 | 정상 공공기관 안내의 오탐과 근거 부족 사이의 절충입니다(ADR 0010) |

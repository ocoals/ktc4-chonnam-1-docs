# 4. 테스트 전략

## 코드 테스트

| 수준 | 무엇을 확인하나 | 방식 |
| --- | --- | --- |
| 유닛 (`ai/tests/`) | 링크 추출, 근거 검증, 결론 관문, 사례 검색 | 가짜 LLM 클라이언트, 네트워크 없음 |
| 통합 (`tests/`) | 스킬 흐름, 결과 확인, 보안, 공식 대조 | FastAPI 테스트 클라이언트, AI와 수집기는 스텁 |
| 계약 | JSON 스키마와 pydantic 모델이 같은지 | 어긋나면 실패 |
| 배포 검증 | 격리 컨테이너의 방화벽과 브라우저 | 배포 뒤 EC2에서 `verify.py` |
| 실기기 | 카드 렌더링, 버튼, 글자 잘림 | 카카오 개발 채널에서 직접 확인 |

테스트는 실제 LLM API와 실제 스미싱 URL을 쓰지 않습니다. 가짜 클라이언트와 고정된 예시 자료를 씁니다.

## AI 응답 품질 점검

| 점검 | 방법 | 상태 |
| --- | --- | --- |
| 근거 충실성 | 인용이 원문에 있는지 코드가 검사 | 자동 |
| 금지 출력 | 안전 보증 표현이 없는지 금지어 검사 | 자동 |
| 폴백 | LLM 실패, 거부, 시간 초과에도 같은 모양의 결과 | 자동 |
| 결론 재현성 | 같은 입력이면 같은 결론 (순수 함수) | 자동 |
| 사례 검색 품질 | 평가셋을 조정용과 확인용으로 나눠 hit@3, 정상 부착률 측정 | 수동 |

## 최근 측정

**사례 검색 (2026-10-31, 확인용 평가셋)**

hit@3은 비슷한 사례 상위 3개 안에 같은 유형의 사례가 들어 있는 비율입니다. 설정은 조정용 평가셋에서만 고르고, 확인용 평가셋은 설정을 정한 뒤 한 번만 쟀습니다.

| 시나리오 | hit@3 |
| --- | --- |
| 스미싱 문자 | 85.0% (40건 중 34건) |
| 링크 없는 사칭 문자 | 91.7% (12건 중 11건) |
| 보이스피싱 통화 | 98.2% (171건 중 168건) |

**링크 추출 (2026-10-31)**: 문자 12건을 2번씩, 24회 모두 기대한 링크를 뽑았고 중앙값 1.7초가 걸렸습니다.

**통화 결론 (대리 평가)**: 실제 정상 통화 4,500건 중 의심 결론은 5건(0.1%)이었습니다. LLM 대신 어휘표로 읽어 잰 값입니다.
